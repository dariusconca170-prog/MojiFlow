# PLAN.md — MediaLingual-Native

Universal Japanese sentence-mining overlay (Rust, eframe/egui). Milestone checklist; this file is updated as milestones complete. Verification gate after **every** milestone:

```
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
cargo build
```

## Milestones

- [x] **M0 — Plan** — `PLAN.md` + `AGENTS.md` created and kept current.

- 2026-10-08: **M5 — Capture — complete, gate passed.** New `src/audio/` module: `ring.rs` is a lock-free SPSC mono `f32` ring storing sample bits in `AtomicU32` slots; the cpal callback pushes with Relaxed stores and a Release `written` horizon, reads Acquire it — no allocation or locking on the real-time thread. One sample of slack means the producer's current slot is never handed to a reader at the wrap boundary; `resolve_range` (pure, tested) clamps stale windows forward and returns `TooOld`/`EmptyRange`. `encode.rs` wraps LAME (`mp3lame_encoder`, mono `f32` in, nearest CBR-bitrate, `FlushNoGap`); peak normalize + frame-sync tests produce a playable MP3. `capture.rs` runs cpal on a dedicated thread (cpal streams aren't `Send` on ALSA), prefers loopback/monitor names, and reconnects with backoff; all PCM formats (incl. `I24`/`U24`) downmix to mono. `src/capture/screen.rs` captures a title-matched window or a clamped manual region via `xcap`, downscales to `max_width`, and JPEG-encodes (round-trip validated). App wires capture at startup, toasts transitions, and shows `audio N.Ns buf` in the status strip. - 2026-10-08: **Always-on-top fix (bug report: "the overlay isn't topmost").** Root cause: eframe 0.36 contains **no `WindowLevel` handling anywhere** in its winit integration, so `ViewportBuilder::with_always_on_top()` was silently dropped — the overlay never received `_NET_WM_STATE_ABOVE` and sat at Z-order-luck (xprop confirmed the property was absent; KWin is the WM here). Fix: `GlobalPointer::set_always_on_top(title, enable)` walks the X tree on the existing second x11rb connection, finds windows by `_NET_WM_NAME` == `platform::OVERLAY_TITLE`, and sends an EWMH `_NET_WM_STATE` ClientMessage (`[action, ABOVE, 0, source=1, 0]`, LE data32 bytes for x11rb 0.14's raw `ClientMessageData`) only when the WM state actually differs. `App` re-asserts every 750 ms (self-healing; honors `config.window.always_on_top`, now actually wired — `main.rs` builder got `with_window_level` gated on it). Windows/macOS return `WindowError::Unsupported`, logged once as a toast. Verified on the live X11 setup: `xprop` now shows `_NET_WM_STATE(ATOM) = … _NET_WM_STATE_ABOVE, _NET_WM_STATE_STAYS_ON_TOP`. Caveat documented (KWin): EWMH above does not beat fullscreen windows. Also investigated and ruled out: "leftover app processes" were a test-harness artifact (`$!` = subshell of `cd … && app &`, and background jobs inherit SIGINT-ignored from non-interactive shells — the app itself installs no signal handlers; `SigCgt` clean, SIGTERM/Ctrl+C from a real terminal work). Gate: fmt/clippy/test/build green, **132 tests** (+1 `net_wm_state_payload_adds_and_removes`).
